\section{Implementação do Front-end}

O front-end do sistema Tropical Mix foi desenvolvido com o objetivo de disponibilizar uma interface web intuitiva, responsiva e integrada aos serviços do back-end. Essa camada é responsável pela interação direta com o usuário, permitindo o acesso às funcionalidades de autenticação, consulta e gerenciamento de produtos, registro de vendas, cadastro de clientes, fornecedores e usuários, além da visualização de informações relacionadas ao estoque e às operações comerciais.

A implementação da interface seguiu a arquitetura definida para o projeto, na qual a camada de apresentação se comunica com a camada de aplicação por meio de requisições HTTP e troca de dados em formato JSON. Essa separação contribui para a modularidade do sistema, permitindo que o front-end seja desenvolvido e mantido de forma independente em relação às regras de negócio implementadas no back-end.

\subsection{Visão geral da implementação}

A implementação do front-end foi organizada com base no uso da biblioteca React, em conjunto com JavaScript, HTML e CSS. O React foi utilizado por possibilitar a construção de interfaces baseadas em componentes reutilizáveis, favorecendo a organização do código, a separação de responsabilidades e a manutenção evolutiva da aplicação.

A aplicação foi estruturada como uma Single Page Application (SPA), ou seja, uma aplicação web em que a navegação entre telas ocorre de forma dinâmica, sem a necessidade de recarregamento completo da página a cada mudança de rota. Esse modelo proporciona uma experiência de uso mais fluida, uma vez que os componentes são renderizados conforme a navegação do usuário e os dados necessários são obtidos por meio de chamadas à API.

No contexto do sistema Tropical Mix, o front-end contempla telas voltadas à autenticação de usuários, página inicial, controle de estoque, registro de vendas, gerenciamento de clientes, fornecedores, usuários e relatórios. Além disso, foram implementados componentes reutilizáveis para navegação, rodapé, notificações e janelas de confirmação, com o objetivo de manter a padronização visual e comportamental da aplicação.

A camada de interface também considera regras de acesso, uma vez que determinadas telas devem estar disponíveis apenas para usuários autenticados. Para isso, foi implementado um mecanismo de proteção de rotas no próprio front-end, baseado na verificação da existência do token de autenticação armazenado no navegador. Dessa forma, usuários não autenticados são redirecionados para a tela de login, preservando o fluxo de acesso definido para o sistema.

\subsection{Estrutura de pastas do front-end}

A estrutura do front-end foi organizada de forma modular, separando arquivos de configuração, componentes reutilizáveis, páginas, serviços e estilos. Essa organização facilita a localização dos arquivos, a manutenção do código e a divisão das responsabilidades entre os elementos da aplicação.

Na raiz do front-end, encontram-se os arquivos de configuração do projeto, como o \texttt{package.json}, responsável por registrar as dependências utilizadas, e o \texttt{vite.config.js}, utilizado na configuração do ambiente de desenvolvimento com Vite. A aplicação utiliza dependências como \texttt{react}, \texttt{react-dom}, \texttt{react-router-dom}, \texttt{axios} e \texttt{react-icons}, além de bibliotecas de apoio ao processo de desenvolvimento e validação do código.

A pasta \texttt{src} concentra o código-fonte principal da aplicação. Dentro dela, o arquivo \texttt{main.jsx} é responsável por inicializar a aplicação React e renderizar o componente principal. O arquivo \texttt{App.jsx}, por sua vez, centraliza a definição das rotas da aplicação e a lógica de proteção de acesso às páginas internas.

A pasta \texttt{components} armazena elementos reutilizáveis da interface, como a barra de navegação, o rodapé, o componente de notificação e o modal de confirmação. Esses componentes são utilizados em diferentes telas da aplicação, reduzindo duplicidade de código e contribuindo para a consistência visual do sistema.

A pasta \texttt{pages} reúne as telas principais do sistema, como Login, Home, Estoque, Vendas, Clientes, Fornecedores, Cadastro, Perfil e Relatório. Cada página possui sua própria estrutura de implementação e arquivo de estilo, permitindo que as funcionalidades sejam desenvolvidas de maneira isolada, sem comprometer o funcionamento das demais partes da aplicação.

\subsection{Tecnologias e bibliotecas utilizadas}

O desenvolvimento do front-end utilizou o React como principal biblioteca para construção da interface. Essa escolha está alinhada à proposta arquitetural do sistema, que prevê uma camada de apresentação moderna, interativa e baseada em componentes. O uso de componentes permite dividir a interface em partes menores e reutilizáveis, o que favorece a manutenção, a legibilidade do código e a evolução do sistema.

O projeto também utiliza o Vite como ferramenta de construção e execução em ambiente de desenvolvimento. O Vite fornece um ambiente leve e rápido para aplicações modernas em JavaScript, simplificando o processo de inicialização, atualização e empacotamento do front-end.

Para o controle de navegação entre páginas, foi utilizada a biblioteca \texttt{react-router-dom}. Essa biblioteca permite definir rotas para a aplicação, associando cada endereço a um componente de página específico. No sistema Tropical Mix, esse recurso é utilizado para organizar o acesso às telas de login, início, estoque, vendas, clientes, fornecedores, cadastro de usuários, perfil e relatório.

A comunicação com o back-end é realizada por meio da biblioteca \texttt{axios}, utilizada para o envio de requisições HTTP à API. Essa biblioteca facilita a execução de operações como listagem, cadastro, edição e consulta de dados, além de permitir o envio do token de autenticação no cabeçalho das requisições protegidas.

A estilização da interface foi desenvolvida com CSS, utilizando arquivos de estilo separados por componente ou página. Essa separação contribui para a organização visual do projeto e permite que cada tela mantenha suas próprias regras de apresentação, respeitando, ao mesmo tempo, o padrão visual definido para o sistema.

\subsection{Roteamento e proteção de rotas}
A navegação entre as páginas do sistema foi implementada com o auxílio da biblioteca \texttt{react-router-dom}, responsável por controlar as rotas internas da aplicação. Esse recurso permite associar diferentes caminhos da URL a componentes específicos, possibilitando que o usuário transite entre as telas do sistema sem a necessidade de recarregamento completo da página.

No arquivo \texttt{App.jsx}, foram definidas as principais rotas do sistema, incluindo a tela de login, a página inicial, o controle de estoque, o registro de vendas, o gerenciamento de clientes, fornecedores, perfil de usuário, cadastro e relatório. A rota inicial, representada por \texttt{/}, direciona o usuário para a tela de autenticação, enquanto as demais rotas representam áreas internas da aplicação.

Para restringir o acesso às páginas internas, foi implementado o componente \texttt{ProtectedRoute}. Esse componente verifica se existe um token de autenticação armazenado no \texttt{localStorage} do navegador. Caso o token não esteja presente, o usuário é redirecionado automaticamente para a tela de login. Caso contrário, o conteúdo da página solicitada é renderizado normalmente.

Além da proteção de acesso, o componente \texttt{ProtectedRoute} também centraliza a exibição de elementos comuns às telas autenticadas, como a barra de navegação e o rodapé. Dessa forma, todas as páginas internas mantêm uma estrutura visual padronizada, evitando a repetição desses componentes em cada tela individualmente.

Esse modelo contribui para a organização da aplicação, pois separa a tela pública de login das telas protegidas do sistema. Também favorece a manutenção do código, uma vez que alterações nos elementos comuns de navegação podem ser realizadas em um único ponto da aplicação.

\subsection{Comunicação com a API}

A comunicação entre o front-end e o back-end foi implementada por meio de requisições HTTP, utilizando a biblioteca \texttt{axios}. Essa biblioteca permite que a interface envie e receba dados da API de forma assíncrona, possibilitando operações como autenticação, listagem de registros, cadastro, edição e consulta de informações.

No sistema Tropical Mix, as chamadas à API são realizadas a partir das páginas da aplicação, de acordo com a funcionalidade executada pelo usuário. Na tela de login, por exemplo, o front-end envia as credenciais informadas pelo usuário para a rota de autenticação do back-end. Quando a autenticação é bem-sucedida, o token retornado pela API é armazenado no \texttt{localStorage}, permitindo que as demais requisições protegidas sejam realizadas posteriormente.

Nas telas internas, o token armazenado é enviado no cabeçalho das requisições por meio do campo \texttt{Authorization}, utilizando o padrão \texttt{Bearer Token}. Esse procedimento permite que o back-end identifique o usuário autenticado e valide se ele possui permissão para acessar ou modificar os dados solicitados.

A tela de estoque, por exemplo, realiza requisições para carregar produtos, categorias e fornecedores. Essas informações são utilizadas para preencher a tabela principal, os filtros laterais e os campos dos formulários de cadastro. Também são realizadas requisições para registrar novos produtos, criar categorias e fornecedores quando necessário, além de atualizar o estado visual da interface após cada operação.

De forma semelhante, a tela de vendas consome dados de clientes, produtos e pedidos. Para exibir as vendas registradas, a interface busca a lista de pedidos e, em seguida, consulta os detalhes de cada venda, permitindo calcular valores totais e apresentar informações resumidas ao usuário. No registro de uma nova venda, o front-end monta um objeto com o cliente, o método de pagamento e os itens adicionados ao carrinho, enviando esse conjunto de dados para a API responsável pelo cadastro do pedido.

As telas de clientes e fornecedores seguem o mesmo princípio de comunicação, utilizando requisições para listar registros existentes, cadastrar novos dados e atualizar informações previamente registradas. Após operações bem-sucedidas, os dados são recarregados para manter a interface sincronizada com o estado atual do banco de dados.

Esse modelo de comunicação contribui para a separação de responsabilidades entre as camadas da aplicação. O front-end concentra-se na apresentação, interação e validação inicial dos dados, enquanto o back-end é responsável por aplicar as regras de negócio, persistir informações e retornar respostas estruturadas para a interface.

\subsection{Componentes reutilizáveis}

A implementação do front-end também contempla o uso de componentes reutilizáveis, com o objetivo de reduzir duplicidade de código, padronizar a interface e facilitar a manutenção da aplicação. Em uma aplicação baseada em React, os componentes representam partes independentes da interface que podem ser utilizadas em diferentes telas, recebendo propriedades e comportamentos conforme a necessidade de cada contexto.

No sistema Tropical Mix, foram implementados componentes comuns para navegação, rodapé, notificações e confirmação de ações. Esses elementos são utilizados em múltiplas páginas da aplicação e contribuem para manter uma experiência visual consistente para o usuário.

O componente de navegação, representado pela barra superior do sistema, concentra os links principais da aplicação, permitindo o acesso às telas de início, estoque, clientes, fornecedores, vendas e relatório. Além disso, o componente apresenta informações relacionadas ao usuário autenticado, como o nome armazenado no navegador, e disponibiliza opções de acesso ao perfil, cadastro de usuário e saída do sistema. A exibição de determinadas opções considera o nível de acesso do usuário, diferenciando funcionalidades disponíveis para administradores e vendedores.

O rodapé foi implementado como um componente separado, utilizado juntamente com a navegação nas rotas protegidas. Essa separação evita a necessidade de repetir a mesma estrutura em cada página interna, favorecendo a organização e a padronização visual da aplicação.

Também foi desenvolvido um componente de notificação, utilizado para exibir mensagens de sucesso, erro, aviso ou informação. Esse componente substitui parte das mensagens nativas do navegador e permite apresentar retornos visuais mais integrados ao padrão da interface. Dessa forma, ações como cadastro, atualização, falha de validação ou erro de comunicação podem ser comunicadas ao usuário de maneira mais clara e menos intrusiva.

Outro elemento reutilizável é o modal de confirmação, utilizado em ações que exigem validação explícita do usuário antes de serem concluídas. Esse componente é especialmente importante para operações que podem alterar o estado dos dados, como ocultar, reativar ou remover registros. O uso desse tipo de confirmação contribui para reduzir ações acidentais e melhora a segurança da interação.

Além dos componentes gerais, algumas telas implementam componentes locais para campos de sugestão e filtros pesquisáveis. Esses campos permitem que o usuário digite livremente ou selecione opções existentes, geralmente exibidas em ordem alfabética. Esse padrão foi utilizado em filtros e formulários com o objetivo de facilitar a busca por produtos, fornecedores, categorias, marcas, sabores e demais informações recorrentes no sistema.

A adoção de componentes reutilizáveis contribui para uma estrutura de front-end mais modular. Com isso, alterações de comportamento ou de estilo podem ser realizadas de forma centralizada, reduzindo o esforço de manutenção e favorecendo a evolução da aplicação.

\subsection{Padrões visuais e experiência do usuário}

A interface do sistema Tropical Mix foi desenvolvida buscando manter consistência visual, clareza na navegação e facilidade de uso. Como o sistema é voltado ao gerenciamento operacional de estoque, vendas, clientes e fornecedores, a experiência do usuário foi considerada um aspecto relevante para reduzir erros durante o uso e tornar as principais ações mais acessíveis.

O padrão visual adotado utiliza uma identidade baseada em tons de roxo, lilás, branco e amarelo, cores associadas à marca Tropical Mix e aplicadas de forma recorrente em botões, barras de navegação, cabeçalhos de modais, filtros e indicadores visuais. Essa padronização permite que diferentes telas sejam reconhecidas como partes de um mesmo sistema, evitando inconsistências visuais entre os módulos.

A Figura~\ref{fig:paleta-cores-interface} apresenta a paleta de cores utilizada na interface da aplicação. O roxo-vinho foi definido como cor institucional principal, o rosa escuro como cor secundária de apoio, o rosa claro como cor de apoio e o amarelo como cor de ação e destaque. Essa organização contribui para a definição de uma hierarquia visual, orientando o uso das cores conforme sua função na interface.

As páginas internas seguem uma estrutura semelhante, composta por título principal, área de ações, tabela de registros, filtros laterais e modais para cadastro ou edição. Esse padrão foi aplicado em telas como estoque, vendas, clientes e fornecedores, facilitando o aprendizado da interface pelo usuário. Uma vez compreendida a lógica de uma tela, a navegação nas demais se torna mais intuitiva.

Os botões de ação também seguem uma hierarquia visual. Ações principais, como adicionar novo registro ou salvar informações, são destacadas com cores mais evidentes. Já ações secundárias, como cancelar, limpar filtros ou fechar modais, recebem menor destaque visual. Essa diferenciação contribui para orientar o usuário sobre a importância de cada ação disponível na interface.

A aplicação também utiliza filtros avançados em painéis laterais, permitindo a busca e segmentação dos dados exibidos nas tabelas. Em diferentes telas, foram implementados filtros por campos como nome, categoria, fornecedor, cliente, vendedor, produto, forma de pagamento, período e faixa de valor. Em alguns casos, os filtros utilizam campos pesquisáveis com sugestões, permitindo que o usuário digite parte do termo desejado ou selecione uma opção existente.

Nas telas com maior quantidade de informações, como estoque e vendas, foram aplicados recursos visuais para destacar situações relevantes. No estoque, por exemplo, produtos com baixa quantidade podem receber indicação visual específica, enquanto lotes vencidos ou próximos do vencimento são representados por etiquetas de status. Esses elementos auxiliam o usuário a identificar rapidamente situações que exigem atenção.

Os modais foram utilizados para concentrar formulários e ações específicas sem retirar o usuário do contexto principal da tela. Dessa forma, operações como adicionar produto, registrar venda, cadastrar fornecedor ou visualizar detalhes podem ocorrer sobre a própria página, mantendo a navegação mais fluida. Em formulários mais extensos, as informações foram agrupadas por seções, como dados do produto, entrada inicial de estoque, dados da venda e carrinho.

A experiência do usuário também foi aprimorada por meio de mensagens de retorno visual. O componente de notificação informa o resultado de ações como cadastro, edição, validação de campos e erros de comunicação. Esse recurso contribui para tornar a interação mais clara, pois o usuário recebe uma resposta imediata após executar uma ação.

Além disso, a utilização de confirmações em ações sensíveis reduz a possibilidade de alterações acidentais. Ao solicitar confirmação antes de determinadas operações, o sistema oferece uma etapa adicional de segurança na interação, especialmente em funcionalidades que modificam o estado dos dados.

Dessa forma, os padrões visuais e comportamentais adotados no front-end contribuem para uma interface mais organizada, consistente e adequada ao uso cotidiano da aplicação, priorizando clareza, previsibilidade e facilidade de manutenção.

\subsection{Telas desenvolvidas}

As telas desenvolvidas no front-end do sistema Tropical Mix foram organizadas de acordo com os principais fluxos operacionais da aplicação. Cada tela foi estruturada para atender a uma funcionalidade específica, mantendo padronização visual, integração com a API e consistência na experiência de uso.

A aplicação contempla telas públicas e telas protegidas. A tela de login representa o ponto de entrada do sistema, enquanto as demais páginas internas dependem da autenticação do usuário para serem acessadas. Essa organização está alinhada ao modelo de rotas protegidas definido no front-end, no qual páginas como início, estoque, vendas, clientes, fornecedores, cadastro, perfil e relatório são acessadas apenas após a validação do token de autenticação.

As interfaces foram desenvolvidas considerando os requisitos funcionais definidos para o sistema, como autenticação de usuários, controle de estoque, registro de vendas, gerenciamento de clientes, fornecedores e usuários, além da visualização de informações gerenciais. Também foram considerados aspectos de usabilidade, como organização dos dados em tabelas, uso de filtros, modais para formulários, mensagens de retorno e padronização dos elementos visuais.

\subsubsection{Tela de login}

A tela de login é responsável por controlar o acesso inicial ao sistema Tropical Mix. Nessa interface, o usuário informa suas credenciais de acesso, compostas por e-mail e senha, para que a autenticação seja realizada junto ao back-end.

Após o envio dos dados, o front-end realiza uma requisição para a rota de autenticação da API. Quando as credenciais são validadas, o token retornado pelo back-end é armazenado no \texttt{localStorage} do navegador. Esse token passa a ser utilizado nas demais requisições protegidas do sistema, permitindo que o usuário acesse as páginas internas da aplicação.

Além do token, a tela também armazena informações derivadas do conteúdo do JWT, como o nome do usuário e seu nível de acesso. Esses dados são utilizados posteriormente na interface, especialmente na barra de navegação, para exibir informações do usuário autenticado e controlar a apresentação de funcionalidades restritas.

A interface de login também contempla a opção de redefinição de senha, acionada por meio do botão ``Esqueci minha senha''. Ao selecionar essa opção, é exibido um modal para preenchimento do e-mail do usuário. A resposta apresentada ao usuário é genérica, informando que, caso o e-mail exista, serão enviadas instruções de recuperação. Essa abordagem contribui para evitar a exposição indevida de informações sobre contas cadastradas.

Visualmente, a tela foi desenvolvida com foco na identificação da marca e na simplicidade do fluxo de entrada. A logo da Tropical Mix é exibida acima do formulário, enquanto o cartão central concentra os campos de autenticação e as ações disponíveis. O uso de fundo em degradê, botões destacados e campos centralizados contribui para uma apresentação mais profissional e objetiva.

\subsubsection{Tela inicial}

A tela inicial, também denominada Home, é apresentada ao usuário após a autenticação bem-sucedida no sistema. Sua função principal é atuar como ponto de acesso às principais áreas da aplicação, organizando visualmente os módulos disponíveis e facilitando a navegação entre as funcionalidades.

Essa página apresenta uma mensagem de boas-vindas ao sistema Tropical Mix e cards de navegação direcionados às áreas de usuários e cadastros, estoque, clientes, fornecedores e vendas. Cada card possui título, breve descrição e link para a respectiva rota interna, permitindo que o usuário acesse rapidamente o módulo desejado.

A estrutura da tela inicial foi desenvolvida com foco na simplicidade e na orientação do usuário. Em vez de apresentar grande volume de dados logo após o login, a página concentra-se em oferecer caminhos claros para as principais operações do sistema. Essa decisão favorece a usabilidade, especialmente para usuários que precisam executar tarefas operacionais de forma objetiva.

Do ponto de vista técnico, a tela utiliza componentes de navegação do \texttt{react-router-dom}, por meio do componente \texttt{Link}. Esse recurso permite que cada card direcione o usuário para uma rota específica da aplicação sem recarregar completamente a página, mantendo o comportamento de Single Page Application.

A tela inicial também segue os padrões visuais definidos para o projeto, utilizando fundo claro, cards com bordas arredondadas, sombras sutis e elementos destacados na paleta institucional da aplicação. Essa padronização contribui para manter a consistência visual entre a página inicial e os demais módulos internos do sistema.

\subsubsection{Tela de estoque}

A tela de estoque é responsável pela visualização e pelo gerenciamento dos produtos cadastrados no sistema Tropical Mix. Essa interface concentra informações essenciais para o controle operacional, como nome do produto, categoria, sabor, quantidade atual, próxima validade, status e último fornecedor vinculado.

A listagem dos produtos é apresentada em formato de tabela, permitindo ao usuário consultar rapidamente os itens disponíveis. Cada linha representa um produto cadastrado e reúne dados provenientes da API de estoque. A tela também apresenta um contador com a quantidade de itens listados, o que auxilia na compreensão do volume de registros exibidos após a aplicação de filtros.

Um dos principais recursos da tela é o painel lateral de filtros avançados. Esse painel permite segmentar os produtos por diferentes critérios, como texto livre, status, categoria, sabor, marca e fornecedor. Os filtros por categoria e status utilizam seleção por caixas de marcação, enquanto outros campos utilizam entradas pesquisáveis com sugestões, permitindo que o usuário digite parte do valor desejado ou selecione opções existentes. Essa abordagem facilita a busca em cenários com maior quantidade de produtos cadastrados.

A tela também utiliza indicadores visuais para destacar situações relevantes no controle de estoque. Produtos com quantidade reduzida recebem uma identificação de estoque baixo, enquanto produtos com lotes vencidos ou próximos da validade são sinalizados por etiquetas de status. Esses elementos auxiliam na tomada de decisão, pois permitem identificar rapidamente produtos que exigem reposição, atenção quanto ao vencimento ou alguma ação administrativa.

O cadastro de novos produtos é realizado por meio de um modal, aberto a partir do botão de adição. O formulário foi organizado em seções, separando os dados gerais do produto da entrada inicial de estoque. Entre os campos disponíveis estão nome do produto, categoria, sabor, marca, custo unitário, fornecedor, número do lote, quantidade inicial e data de vencimento. Essa separação contribui para tornar o preenchimento mais claro e reduzir erros durante o cadastro.

A tela também contempla validações iniciais no front-end, como a obrigatoriedade de informar nome do produto, categoria, fornecedor, quantidade inicial e custo unitário. Além disso, a data de vencimento é validada para evitar o cadastro de produtos já vencidos. Essas validações não substituem as regras aplicadas no back-end, mas funcionam como uma primeira camada de orientação ao usuário.

Do ponto de vista de integração, a tela de estoque realiza requisições para diferentes rotas da API. São consumidos dados de produtos, categorias, fornecedores e usuários, utilizados tanto na tabela principal quanto nos filtros e formulários. No cadastro de um novo produto, a interface também possui lógica para obter ou criar categorias e fornecedores, permitindo que novos valores sejam incorporados ao sistema durante o próprio fluxo de cadastro.

Além da visualização e do cadastro, a tela permite acessar os detalhes de um produto específico por meio do botão ``Detalhes''. Essa ação abre a página de detalhe do produto em uma nova aba, possibilitando uma análise mais aprofundada sem interromper completamente a visualização da listagem geral do estoque.

Dessa forma, a tela de estoque representa um dos principais módulos operacionais do sistema, pois centraliza o acompanhamento dos produtos, apoia o controle de validade, facilita a localização de registros e integra ações de cadastro, consulta e navegação para detalhes.

\subsubsection{Tela de detalhe do produto}

A tela de detalhe do produto foi desenvolvida para apresentar informações consolidadas de um item específico do estoque, permitindo uma análise mais aprofundada do produto selecionado na listagem principal. Diferentemente da tela geral de estoque, que apresenta uma visão resumida dos produtos cadastrados, essa interface concentra dados individuais, histórico de entradas e informações relacionadas aos lotes disponíveis.

O acesso a essa tela ocorre a partir do botão ``Detalhes'', disponível na tabela da tela de estoque. Ao selecionar essa opção, o sistema abre uma página específica do produto, permitindo que o usuário consulte suas informações sem perder a referência da listagem geral. Essa decisão de navegação favorece a comparação entre produtos e evita interrupções no fluxo principal de consulta.

Na parte superior da página, são exibidas informações gerais do produto, como nome, categoria, sabor, marca, estoque atual, custo unitário e custo total do estoque. O custo total é calculado a partir dos lotes exibidos, considerando a quantidade disponível e o valor unitário de cada lote. Dessa forma, a interface permite uma visão financeira aproximada do estoque disponível daquele produto.

A tela também apresenta um indicador relacionado à validade dos lotes. Esse recurso considera tanto lotes vencidos quanto lotes próximos do vencimento, definidos como aqueles com data de vencimento em até 45 dias. Quando acionado, o indicador permite filtrar a tabela de lotes para exibir apenas os registros que exigem maior atenção, facilitando a identificação de produtos que podem gerar perdas ou demandar ação operacional.

A tabela de lotes apresenta informações detalhadas sobre cada entrada de estoque vinculada ao produto, incluindo validade, número do lote, fornecedor, quantidade recebida, quantidade disponível, custo unitário, custo total do lote e data de entrada. Essa organização permite rastrear a origem e a situação de cada lote, contribuindo para maior controle sobre validade, saldo e custo de reposição.

Além da consulta, a tela permite registrar uma nova entrada de estoque por meio do botão ``Registrar entrada''. Ao acionar essa opção, é exibido um modal para preenchimento das informações do novo abastecimento, como fornecedor, quantidade recebida, valor unitário, data de vencimento e número do lote. Após o envio, a interface realiza uma requisição para a API de estoque e atualiza os dados da página, mantendo os cards e a tabela de lotes sincronizados com as informações mais recentes.

Essa tela também apoia a lógica de controle por lote, que é especialmente importante para produtos com validade. Ao separar os abastecimentos de um mesmo produto, o sistema permite acompanhar diferentes datas de vencimento e quantidades disponíveis, em vez de tratar o produto apenas como um saldo único. Essa abordagem contribui para um controle mais preciso e para a identificação de lotes vencidos ou próximos do vencimento.

Dessa forma, a tela de detalhe do produto complementa a tela principal de estoque, oferecendo uma visão operacional mais completa sobre cada item cadastrado. Sua implementação favorece o acompanhamento de entradas, validade, custo e disponibilidade, aspectos essenciais para a gestão de produtos perecíveis ou sujeitos a controle por lote.

\subsubsection{Tela de vendas}

A tela de vendas foi desenvolvida para registrar, consultar e acompanhar os pedidos realizados no sistema Tropical Mix. Essa interface centraliza as operações relacionadas às vendas, permitindo visualizar os registros já existentes, aplicar filtros de busca, consultar detalhes de pedidos e cadastrar novas vendas.

A listagem das vendas é apresentada em formato de tabela, contendo informações como data do pedido, cliente, vendedor, forma de pagamento, itens vendidos e valor total. Para compor essas informações, o front-end consulta a lista de pedidos e, posteriormente, busca os detalhes de cada pedido, permitindo calcular o total da venda a partir dos itens vinculados.

A tela possui um painel lateral de filtros avançados, utilizado para facilitar a localização de registros específicos. Entre os critérios disponíveis, estão busca textual, forma de pagamento, intervalo de datas, cliente, vendedor, itens vendidos e faixa de valor. Alguns desses campos utilizam sugestões pesquisáveis, permitindo maior flexibilidade na filtragem dos dados e melhor usabilidade em cenários com maior volume de vendas registradas.

O cadastro de uma nova venda é realizado por meio de um modal, aberto a partir do botão de adição. Nesse fluxo, o usuário seleciona o cliente, a forma de pagamento e os produtos que serão incluídos no pedido. A interface também permite a criação de um novo cliente durante o processo de venda, caso ele ainda não esteja cadastrado no sistema. Essa funcionalidade reduz a necessidade de interromper o fluxo de registro para acessar outra tela.

A seleção dos produtos foi organizada de forma progressiva, considerando nome, sabor e marca. A partir dessas informações, o sistema identifica o produto correspondente e permite adicioná-lo ao carrinho da venda. Antes da inclusão, a interface verifica se os campos necessários foram preenchidos e se a quantidade solicitada não excede a quantidade disponível em estoque. Essa validação auxilia o usuário durante o preenchimento e reduz a possibilidade de inconsistências.

Os itens adicionados à venda são exibidos em um carrinho, no qual são apresentadas informações como produto, quantidade, preço unitário e subtotal. O valor total da venda é calculado a partir da soma dos subtotais dos itens adicionados. Esse recurso permite que o usuário confira os dados antes de finalizar o pedido.

Ao finalizar a venda, o front-end monta uma estrutura de dados contendo o cliente, a forma de pagamento e a lista de itens do pedido. Essas informações são enviadas para a API responsável pelo registro da venda. Após o processamento pelo back-end, o estoque é atualizado conforme as regras de negócio implementadas, e a interface recarrega a listagem para refletir a nova operação.

A tela também contempla a visualização de detalhes de uma venda já registrada. Ao acessar os detalhes, o usuário pode consultar os itens que compõem o pedido, suas quantidades, preços unitários e subtotais. Essa funcionalidade contribui para a rastreabilidade das operações e facilita conferências posteriores.

Dessa forma, a tela de vendas integra consulta, filtragem, cadastro e detalhamento de pedidos em um único módulo. Sua implementação contribui para o controle das transações comerciais da loja, mantendo a relação entre cliente, vendedor, produtos vendidos, forma de pagamento e atualização do estoque.

\subsubsection{Tela de clientes}

A tela de clientes foi desenvolvida para permitir o gerenciamento dos registros de clientes vinculados às operações comerciais da loja Tropical Mix. Essa interface possibilita a consulta, cadastro e edição de clientes, mantendo informações necessárias para o registro de vendas e para a identificação dos compradores no sistema.

A listagem dos clientes é apresentada em formato de tabela, seguindo o mesmo padrão visual utilizado em outros módulos administrativos da aplicação. Entre os dados exibidos, estão informações como nome ou razão social, CPF ou CNPJ, telefone, e-mail e endereço. Essa estrutura permite que o usuário consulte rapidamente os clientes cadastrados e localize registros específicos quando necessário.

A tela também contempla recursos de filtragem, permitindo a busca por diferentes campos relacionados ao cadastro do cliente. O uso de filtros contribui para melhorar a usabilidade da interface, especialmente em cenários com maior volume de registros. Essa abordagem mantém a coerência com os demais módulos do sistema, nos quais a segmentação dos dados é utilizada como recurso de apoio à navegação e à consulta.

O cadastro e a edição de clientes são realizados por meio de modal, evitando que o usuário seja redirecionado para outra página durante a operação. Esse comportamento mantém o contexto da tela principal e torna o fluxo de uso mais direto. O formulário reúne os principais dados cadastrais do cliente, como nome ou razão social, CPF ou CNPJ, telefone, e-mail e endereço.

Do ponto de vista de integração, a tela se comunica com a API para listar, cadastrar e atualizar os registros de clientes. Após a realização de uma operação, a listagem é atualizada para refletir as informações mais recentes armazenadas no banco de dados. Esse comportamento mantém a interface sincronizada com a camada de persistência.

A tela de clientes também possui relação direta com a tela de vendas, uma vez que o registro de uma venda exige a seleção de um cliente. Dessa forma, o cadastro adequado desses dados contribui para a consistência das transações comerciais registradas no sistema.

\subsubsection{Tela de fornecedores}

A tela de fornecedores foi implementada para possibilitar o cadastro, consulta e atualização dos fornecedores relacionados aos produtos e às entradas de estoque. A estrutura da tela segue o padrão utilizado nos demais módulos administrativos, com título, área de ações, tabela de registros, filtros laterais e modal de cadastro ou edição. Na tabela principal, são exibidos os principais dados dos fornecedores, como razão social, CNPJ, telefone e e-mail.

O formulário solicita os dados principais do fornecedor e permite que as informações sejam registradas sem que o usuário precise sair da tela atual. O mesmo modal também é utilizado para edição, alterando seu comportamento conforme exista ou não um fornecedor selecionado para atualização.

A tela realiza comunicação com a API para buscar a lista de fornecedores, cadastrar novos registros e atualizar dados existentes. Após cada operação, os dados são recarregados para manter a tabela atualizada. Esse comportamento contribui para a consistência entre a interface e os dados armazenados.

Além de sua função cadastral, a tela de fornecedores possui relação direta com o controle de estoque. Ao cadastrar um produto ou registrar uma entrada, o sistema permite vincular o item a um fornecedor, o que favorece a rastreabilidade das entradas de mercadoria e o acompanhamento da origem dos produtos. \subsubsection{Tela de gerenciamento de usuários}

A tela de gerenciamento de usuários tem como objetivo controlar o acesso de pessoas autorizadas ao sistema Tropical Mix. Essa funcionalidade está relacionada à segurança da aplicação, pois permite administrar quais usuários podem acessar o sistema e qual nível de permissão será atribuído a cada um.

Na implementação atual, a funcionalidade de cadastro de usuários permite informar nome, e-mail, senha e nível de acesso. O nível de acesso pode ser definido como vendedor ou administrador, sendo utilizado posteriormente para controlar a exibição de funcionalidades específicas na interface, como o acesso à opção de cadastro de usuários na barra de navegação.

A tela possui validação inicial de senha, exigindo que o valor informado atenda a critérios mínimos de segurança. Caso a senha não esteja adequada, a interface apresenta uma mensagem de erro antes do envio dos dados ao back-end. Essa validação atua como uma primeira camada de orientação ao usuário, embora a segurança definitiva dependa também das regras aplicadas no servidor.

O cadastro é realizado por meio de requisição à API, com envio do token de autenticação no cabeçalho da chamada. Dessa forma, a operação fica vinculada ao usuário autenticado e pode ser controlada conforme as permissões definidas no back-end. Após o cadastro, o usuário é redirecionado para a página inicial.

Apesar da existência da tela de cadastro, foi identificada a necessidade de evoluir essa funcionalidade para uma tela administrativa mais completa de gerenciamento de usuários. A proposta de ajuste prevê a substituição da ideia de apenas cadastrar usuários por uma interface capaz de listar, cadastrar, editar e desativar usuários, sem que o administrador precise definir manualmente a senha inicial. Essa melhoria também prevê a exibição de dados como nome, e-mail, CPF, nível de acesso e status, além do uso de fluxo de primeiro acesso por e-mail. :contentReference[oaicite:3]{index=3}

Essa adaptação contribui para maior segurança, rastreabilidade e organização do controle de acesso ao sistema.


\subsection{Tratamento de erros e feedback ao usuário}

O tratamento de erros e o retorno visual ao usuário foram considerados aspectos importantes na implementação do front-end do sistema Tropical Mix. Como a aplicação depende da interação constante entre usuário, interface e API, é necessário que o sistema informe de forma clara quando uma ação foi concluída com sucesso, quando há campos obrigatórios não preenchidos ou quando ocorre alguma falha de comunicação com o back-end.

Para isso, foi implementado um componente reutilizável de notificação, utilizado em diferentes telas da aplicação. Esse componente permite exibir mensagens de sucesso, erro, aviso ou informação, de acordo com o tipo de retorno obtido durante a operação. Visualmente, as notificações aparecem sobre a interface, em posição fixa, com cores e estilos diferenciados conforme a natureza da mensagem.

O uso desse componente substitui parte das mensagens nativas do navegador, como o \texttt{alert()}, permitindo uma experiência mais integrada ao padrão visual do sistema. Dessa forma, ações como salvar produto, cadastrar fornecedor, registrar venda, validar campos obrigatórios ou informar falhas de comunicação são apresentadas de maneira mais clara e menos intrusiva ao usuário.

Além das notificações, algumas telas utilizam validações diretamente no front-end antes do envio dos dados para a API. Na tela de estoque, por exemplo, o sistema verifica se campos obrigatórios foram preenchidos antes do cadastro de um produto, como nome, categoria, fornecedor, quantidade inicial e custo unitário. Também há validação para evitar o cadastro de produto com data de vencimento anterior à data atual.

Na tela de vendas, a interface verifica se o cliente foi selecionado e se há itens no carrinho antes de permitir a finalização do pedido. Também é realizada a validação da quantidade solicitada, impedindo que o usuário adicione ao carrinho uma quantidade superior ao estoque disponível. Essas verificações contribuem para reduzir erros operacionais e orientar o usuário durante o preenchimento dos formulários.

O sistema também utiliza modais de confirmação em ações sensíveis. Esse recurso é empregado em operações que modificam o estado de registros, como ocultar ou reativar produtos. Antes da execução da ação, o usuário precisa confirmar sua intenção, reduzindo a possibilidade de alterações acidentais.

Apesar das validações existentes no front-end, é importante destacar que elas não substituem as validações do back-end. A camada de interface atua como uma primeira etapa de orientação e prevenção de erros, enquanto o back-end permanece responsável por aplicar regras de negócio, validar permissões e garantir a integridade dos dados armazenados.

Dessa forma, o tratamento de erros e feedback ao usuário contribui para uma experiência de uso mais segura, compreensível e consistente, permitindo que o usuário acompanhe o resultado das ações executadas e corrija eventuais problemas durante a interação com o sistema.
